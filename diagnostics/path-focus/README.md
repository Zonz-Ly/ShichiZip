# ShichiZip 聚焦對照（獨立手動調查）

本程式調查我們在 PR #67 寫入上游的右鍵地址欄：新視窗第一次程式化聚焦後，再點一次輸入框會重播焦點環動畫。原版也能重現，不能據此認定與我們的舊實作無關。

產品來源以 `cedddeb` 的已確認外觀版本為基準；沒有改正式產品檔案。這裡複製了實際 `FileManagerTitlePathField` 與 `FileManagerPathToolbar`。後者只將參數型別放寬為 `NSTextField`，以承載純原生參考；路徑標籤 localizer 在探針中固定回傳 Path。 探針以標題列區域接收右鍵，不複製完整應用的標題 AX 定位與窗格；因此必須先確認 C 能重現，才能解讀其他場景。

## 如何操作

1. 在目標 macOS 27 開啟 Action 產生的獨立 App，不需要安裝 Xcode。
2. 若系統詢問桌面存取權，允許它建立 `ShichiZip-Focus-Comparison` 日誌資料夾。
3. 先選 C，按「開啟全新對照視窗」。在對照視窗上方標題列按右鍵；等藍色焦點環出現，再左鍵點輸入框一次。
4. 回到控制視窗，按「有重播」或「沒有重播」。
5. **若 C 沒重現，停止其他場景並回報；其餘比較不能據此證明根因。**
6. 若 C 重現，再依序測 A、B、D、E、F，每次用按鈕建立全新視窗。B 開始時已有輸入框，可以在上方輸入框按右鍵開始。
7. 測完按「結束對照」，將桌面的日誌資料夾一起交回。

## 場景

| 場景 | 要區分的因素 |
| --- | --- |
| A 原生內容區文字框 | 不使用工具列切換，觀察原生文字框的程式化聚焦後首次點擊 |
| B 原生工具列文字框 | 文字框一開始就放在工具列中，不替換工具列 |
| C 我們目前的切換方式 | 在右鍵事件內換成地址欄工具列，立即 selectText；保留 9 pt |
| D 下一輪再聚焦 | 與 C 相同，只將首次聚焦交到下一輪主佇列，無固定毫秒延遲 |
| E 預先建立編輯器 | 視窗出現前呼叫公開 fieldEditor API 建立共享編輯器，之後走 C 的流程 |
| F 無 9 pt 的原生對照 | 和 C 一樣切換工具列，但改用未加自訂內距的原生 NSTextField |

F 只用於隔離影響，不代表要刪掉產品已確認的 9 pt 效果。

日誌記錄場景、視窗／編輯器身分、第一回應者、原生 cell 焦點狀態、幾何、編輯器內距與手動結果，不記錄輸入框的文字內容。任何場景差異都要結合 C 是否成功重現來解讀。

本地 SDK 15.2 檢查副本只為能編譯，將尚未宣告的 extraLarge 符號暫換為 large；Action 使用原始程式碼與 Xcode 27.2 SDK。macOS 14 的結果不能代替 macOS 27 動畫驗證。

程式使用 LSUIElement／accessory 模式，請直接從解壓目錄執行，不必搬入 Applications。關閉所有視窗或按「結束對照」會退出。Action 只構建，不執行此程式或自動化測試。
